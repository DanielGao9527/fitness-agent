# Fitness 知识检索评测样本 v1

新增的[单/两轮语义对照 v1](retrieval_quality/v1/README.md)使用另一份冻结的 24 条自建题，包含计划、受预算执行与人工答案复核；开发 12 题已复核标签并完成[真实运行](results/e3-dev-live-2026-10-16.json)，回答人工复核仍待办，留出未授权。它与下方 260 QA 的文档召回及固定响应流程回放分别报告。

`fitness_qa.jsonl` 是依据本项目已审核公共知识摘要拟定的 **260 条中文 QA**：236 条在固定语料中有依据，24 条在该语料中证据不足。问题由 AI 逐题编写，参考答案取自对应摘要；这不是用户真实提问日志、真人评测，也不是独立外部 gold benchmark。尚未进行独立人工逐题复核。

拟题阶段没有查看任何检索排名、运行原检索或增强检索，也没有根据算法得分筛选题目。后续评测已于 2026-09-24 完成，保留所有方案结果；不得通过删除难题、修改相关块标注或使用 test 调参制造提升。

最新结果：见[内部开发/留出报告](../docs/archive/2026-09/RETRIEVAL_ENHANCEMENT.md)与[外部 T2 固定抽样对照](../docs/archive/2026-09/T2_RETRIEVAL_EVALUATION.md)。内部接近满分仅用于有限回归，不作为主要对外质量指标；外部 100 题、1,000 文档对照独立报告，不是官方全库成绩。全题集的真实答案质量和独立人工逐题审核仍未完成。

## 字段

每行是一条 UTF-8 JSON 对象：

| 字段 | 含义 |
| --- | --- |
| `id` | 固定样本 ID，`fitness-qa-001` 至 `fitness-qa-260` |
| `question` | 原创中文问题，未复制旧 16 条回归题 |
| `reference_answer` | 可答题为主证据块的审核摘要全文；证据不足题说明具体缺失条件或资料。不是模型在线回答结果 |
| `relevant_chunk_ids` | 已标注的充分相关知识块 ID，格式为 `source_id:section_id`；证据不足题为空数组 |
| `group_id` | 语义分组，同一知识块及同类动作变体集中在同一个划分中 |
| `split` | `dev` 或 `test` |
| `category` | `training` 或 `nutrition`，用于分领域分析；全库检索评测时不能把正确领域标签偷偷作为查询过滤条件 |
| `answerable` | 是否能仅凭固定版本的公共知识语料回答问题，不代表完整应用的其他数据库或工具也无法回答 |
| `evidence_excerpt` | 可答题的主证据摘要原文；证据不足题为空字符串 |

参考答案直接保留摘要，目的是明确证据范围。例如标签上的每份大小不等于个人建议份量，通用加重参考不等于可以自动修改记录。它可能包含超出单个问题所需的说明，不适合用字符串完全相等来判定回答质量。

## dev / test 的边界

1. 先按证据主题分组，再固定划分；相同知识块的同义问法没有被随机拆到两边。卧推变体、划船变体、俯卧撑变体等分别按主题集中。
2. test 保留胸部飞鸟、划船、垂直拉、深蹲、肘伸展、腿弯举、提踵、对侧核心伸展、推肩、蔬果、奶类等 11 个可答主题组，以及 12 个证据不足主题组。
3. 旧 `tests/test_knowledge.py` 的 16 条回归问题没有复制到这里；其 15 个目标知识块全部留在 dev，相关的一般活动强度和肌肉强化主题也保守放在 dev。旧题单独保持回归用途。
4. dev 用来选择中文词项处理、融合参数、候选数和其他实现细节。配置选定并记录后再测 test。已经据 test 错误改过的版本必须披露，不能继续把它称为未见留出验证。
5. 这是按项目语料拟题后的内部留出集。题目作者已看到语料，团队能读取文件；没有外部盲测的隔离条件，不能把 test 包装成独立第三方认证。
6. 后续资料或题目修改应另建版本并记录新 SHA-256；基线和增强版本始终使用相同语料、问题、相关性标注及有效日期。

## 相关性标注的局限

大多数题标注一个主证据块；3 条明确可由其他块充分支持的题补了第二个相关块。标注经过按摘要的静态核对，**没有对所有 133 个块逐题做穷尽相关性判定或多标注者一致性评估**。

- 某些未标注块也可能正确支持答案；不能仅因不在列表就断言它无关。
- 当前 Recall 是“相对已标注相关块的 Recall”。单相关块时 Recall@k 与 Hit@k 等价，不应写成真实用户问题的全面召回率。
- 当前只有二元相关性；nDCG 不包含“部分相关、一般相关、高度相关”等分级人工标注。
- 相同动作的两个问题和同一摘要的多个问题并非统计独立；如给置信区间，优先按 `group_id` 重采样，并另报组级/领域级均值。
- 改进标注应在比较前统一规则、人工盲审、对全部方案一致生效，保留修订记录。不能只为某一方案补有利 qrels。

## 怎样使用与报告

1. **可答 236 条**用于比较词法基线、分词变化、纯向量与混合检索；报告 Recall@3/6/10/20、MRR@10、nDCG@10，以及延迟和云端调用量。开发结果与留出结果分开，训练与营养分开。
2. **证据不足 24 条**单独报告，不纳入有答案 Recall/MRR/nDCG 的分母。它们可能有主题相近的检索结果；例如蛋白质食物分类不能回答每天吃几克。没有命中与正确识别证据不足不是一回事。
3. 回答是否受证据支持、是否正确停止，需要额外答案层评测或人工复核。仅凭搜索返回非空或 Recall 提高，不能声称幻觉率下降、整轮问答更安全或端到端成功率提升。
4. 先记录实际基线，再在完全相同输入下记录增强结果；保留失败和退步。词法离线结果、真实云向量结果、模拟向量测试结果必须分开，不得把 mock 的排名作为语义检索效果。
5. 公开中文检索 benchmark（例如 T2Retrieval）独立运行、独立报告。不能与这份依据 Fitness 语料生成的内部 QA 混合成一个未经解释的总体分数。
6. 对外说明里的效果数值只能引用可复现的真实运行报告，并写明数据范围、样本数和指标。数据文件本身不证明检索提升。

## 拟题阶段的静态校验

以下是拟题完成时执行的无网络、无模型、无检索的结构与来源校验；后续真实检索运行另见上方报告：

- 260 行 JSON 均可解析，ID 唯一；问题做 NFKC、大小写和标点归一化后仍无完全重复。
- 可答题均有有效的块 ID；主证据和参考答案与对应摘要原文一致，来源均在固定日期为 approved 且未过复核期。
- 24 条证据不足题的相关块为空；每条有具体证据缺口说明。
- 107 个标注块不存在跨 dev/test 泄漏，61 个语义组也不存在跨划分泄漏。
- 与旧 16 条题没有文字完全相同的问题，旧题目标块没有进入 test。
- 拟题阶段没有执行检索效果比较或真实云模型调用。后续检索评测已完成；仍未进行独立人工逐题语义审核或真人盲测。

资料来源的审核状态只表示项目所记录的审核边界，并不自动产生新的授权或外部权威认证。分发语料摘要或评测集时，应保留项目现有的来源与使用边界说明。
