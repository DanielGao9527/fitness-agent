# Fitness Agent · 健身管理助手

一个中文、多用户的饮食与训练管理应用。将实际记录、可追溯的公共知识和 AI 辅助理解结合起来，帮助用户核对饮食、制定当天建议并回顾变化。

代码仓库：[DanielGao9527/fitness-agent](https://github.com/DanielGao9527/fitness-agent)。[查看已交付增强版](https://github.com/DanielGao9527/fitness-agent/tree/codex/fitness-hybrid-retrieval)，分支为 `codex/fitness-hybrid-retrieval`。

## 可以做什么

- **记录饮食与训练**：支持手动填写，以及可选的文字解析、语音转写和饮食照片识别；先核对再保存。
- **管理档案与目标**：维护个人资料、体测历史、长期能量目标和单日调整，保留历史日期的独立记录。
- **安排后续餐次**：结合目标、已记录摄入、食物限制和有限食材目录，给出食材、份量与营养估算；支持在对话中修改指定餐次。
- **给出当天训练建议**：按三／四／五分化、明确器械、经验、可用时间及近七天实际训练编排动作与正式组数。
- **在主聊天问一般知识**：按本地审核摘要回答，展示来源及适用范围；与个人配餐、训练安排分流，知识问答可单独启用。
- **隔离不同用户的数据**：账号会话绑定身份，记录、草稿、建议、对话与调用次数按用户管理。

建议、估算与实际完成记录分别保存。生成一份餐单或训练建议不会自动变成“已经吃过”或“已经练过”。

## 实现思路

前端使用原生 HTML、CSS 和 JavaScript，由 FastAPI 同源提供页面和接口。SQLite 保存用户数据，独立的 SQLite FTS5 索引检索知识摘要。千问负责可选的语言理解、识别与估算；业务服务负责输入校验、访问控制、数据持久化及推荐约束。

知识检索默认使用 jieba 搜索分词、FTS5/BM25 与云端 embedding 的 RRF 融合；无密钥或无匹配向量缓存时明确退到 jieba 词法。旧双字词项仍可配置并保留作评测基线。文档向量需要显式构建，启动应用不会付费建库。知识块仍是人工整理的审核摘要；检索增强没有引入自动文档分块或自由生成知识答案。接入和效果记录见[检索增强说明](docs/archive/2026-09/RETRIEVAL_ENHANCEMENT.md)。

对话记忆已支持本人经核对旧原话按需找回、用户保存的精简笔记，以及带来源的摘录候选。器械经过人工确认后按本次、今天或长期生效；更正、到期及来源变化会使受影响的旧结果失效。首版真实模型、固定响应回放和上述新表达同题对照分别留证；范围确认阻断已修复并离线验证，新提示词真实效果仍待验证，见[记忆状态](docs/STATUS.md)与[架构](docs/ARCHITECTURE.md)。

交流记忆也可从本人对话选择连续原话，核对后保存；来源更正或删除时停用，手工修改后作为新内容确认。集合版本可拦截过时核对及空列表的并发变化。本机原库已备份升级至 v22，个人记忆与公共知识仍分别管理。

配餐使用 SciPy／HiGHS 进行本地联合配量，并独立复核营养区间。训练建议由审核动作目录和规则编排。当前助手是受约束的业务流程，模型不能自由执行系统命令或直接写入用户记录。

## 本地启动

使用 **Python 3.12**。从仓库根目录执行以下命令；首次运行会创建本地数据库。无需配置模型密钥，即可注册账号、维护档案和手动记录。

Windows PowerShell：

```powershell
.\scripts\setup.ps1
.\scripts\start.ps1
```

打开终端显示的地址，默认是 `http://127.0.0.1:8765`。端口被占用时明确停止，不自动换端口启动第二份服务。

本机已有的 Fitness 工作区统一使用 `fitness-agent/scripts/start.ps1`：它复用原虚拟环境和账号数据库，直接启动本仓库的增强代码。已有模型密钥时默认打开助手等 AI 能力；缺少密钥仍可手动记录，`-ManualOnly` 可显式关闭云模型能力。外层 `app:app` 兼容入口也指向同一实现。独立克隆本仓库时使用上面的标准安装步骤。

其他环境也可以按标准虚拟环境方式启动：

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock.txt
.venv/bin/python -m uvicorn app:app --host 127.0.0.1 --port 8765 --no-proxy-headers
```

以上是本地启动入口，Linux 安装与云端行为需在目标环境验证。本地启动命令不等同于公网部署配置。

## 可选 AI 能力

配置字段见 [.env.example](.env.example)。它是变量说明模板，应用不会自动加载 `.env` 文件；将需要的变量设置到启动进程环境，或按[部署说明](docs/DEPLOYMENT.md)配置服务器服务。

密钥只设置在后端。模型能力默认关闭，文字理解、语音、照片、营养估算和建议可分别启用。主动解析或生成可能产生供应商费用；调用次数限制不是金额预算。缺少配置时，页面会提示相应能力不可用，手动记录仍能使用。

默认 `FITNESS_RETRIEVAL_MODE=hybrid`、`FITNESS_RETRIEVAL_TOKENIZER=jieba`。已有有效文档向量时，一次查询会编码问题并计入使用次数；缓存缺失、损坏或不匹配时明确降级为词法检索，不自动重建。E3 的证据不足自纠正最多再做一次检索及一次证据判断，所有调用继续计入认证额度；相同候选、越界改写或达到上限就停止。主聊天的重复请求复用本轮状态，不自动重试。[E3 实现与边界](docs/archive/2026-09/E3_BOUNDED_RETRIEVAL.md)、[配置](docs/CONFIGURATION.md)及[脚本说明](scripts/README.md)记录了复现方式。

本机完成依赖安装后，可用 `scripts/start.ps1 -EnableKnowledge` 启动默认组合；启动脚本会覆盖继承的旧检索环境变量。向量缓存必须事先显式构建；无密钥或缓存不可用会报告词法降级，不能据此声称运行了混合检索。仅重放旧基线时使用 `scripts/start.ps1 -UseLexicalBaseline`，或直接运行应用并同时设置 `FITNESS_RETRIEVAL_MODE=lexical` 与 `FITNESS_RETRIEVAL_TOKENIZER=bigram`。

## 测试

在仓库根目录使用项目虚拟环境运行：

```powershell
.\.venv\Scripts\python.exe -m pytest
```

Linux／macOS 使用 `.venv/bin/python -m pytest`。Python 回归测试使用隔离数据库和模型替身，不要求真实 API Key。Node 单元测试及浏览器流程的运行方式见 [tests/README.md](tests/README.md)。

自动化测试验证工程行为；模型替身通过不代表真实模型质量、营养准确率、实体手机兼容性或公网部署已经验收。

离线检索评测另使用 [260 条项目 QA](evals/README.md)，比较原词法、jieba、纯向量与 RRF。它是依据公开摘要编写的内部题集，不是真实用户日志或外部权威基准；开发集与留出集分别报告，实际结果以版本化运行报告为准。

## 数据与能力边界

- 适用于无伤病的一般成人健身管理，不提供医疗、康复或伤病处方。
- 营养与运动消耗均可能包含估算和假设；未知值不会被当成零。食材与动作目录有限，不保证任意条件下都能给出建议。
- 食物过敏和明确禁忌是配餐限制；有限映射不代表完整识别所有过敏原、加工配方或交叉接触风险。
- 饮食建议只给食材与份量；训练可用时间是上限，不会为了填满时间无限增加训练量。
- 运行时使用已整理的来源，不联网抓取资料补齐缺口。来源审核与版权说明见[知识来源](docs/KNOWLEDGE_SOURCES.md)。
- 密钥、用户数据库、备份、上传图片、日志和测试产物不属于公开源码，不应进入 Git 历史或静态目录。
