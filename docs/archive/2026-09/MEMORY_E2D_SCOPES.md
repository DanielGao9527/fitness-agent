# E2d.2：从器械原话到有期限的个人条件

本增量在 E2d.1 的字段版本之上，接入受限语义候选、本次/今天/长期范围、确认页面、到期与最终训练建议。只覆盖已支持的器械词表；没有扩展医疗训练或任意个人事实，也没有接入公共知识自沉淀。

## 用一个例子理解

用户说“我训练的地方只有哑铃”，千问在原有一次理解调用中输出器械原话、消息版本及建议范围。程序核对原话与否定条件，再显示确认卡。没有明确时间的结构化候选不默认永久保存，用户选择作用范围后确认：

| 用户选择 | 确认后存放位置 | 新会话 | 停止使用的条件 |
| --- | --- | --- | --- |
| 本次 | 当前对话的结构化条件 | 不沿用 | 更正档案、删除该对话、最晚北京时间零点 |
| 今天 | 私人 SQLite 的当前当天条件 | 当天会话可读取 | 更正/清空档案、更新当天条件、删除来源对话、北京时间零点 |
| 长期 | 现有 `profiles.equipment`，附事实来源和递增版本 | 读取当前档案 | 在档案或新确认中更正/清空 |

例如长期器械为哑铃，今天去别处只能徒手：确认“今天”后，新会话只问“今天练什么”，最终建议使用徒手。翌日不再沿用临时条件，读取长期哑铃档案。如果当天还有“这次只用弹力带”，这个对话使用本次条件，其他当天对话继续使用当天条件。

优先级是 **有效本次条件 → 有效当天条件 → 当前长期档案**。每次生成建议都从当前状态核对，而非靠向量检索猜哪句话更新。长期条件和当天条件确认后不再复制成另一个会话覆盖值，避免旧复制值遮蔽后来的更正。

“本次”在本版定义为当前聊天、最晚当天结束；不是自动检测训练结束。当天条件只用于对话日期与北京时间今天一致的会话。未来日期、过去日期和多天期限尚不支持，需另行澄清。到期是停止参与建议，不等于删除原始聊天或清除历史数据库内容。

## 四块代码及各自作用

1. `schemas.py` 和 `prompts/coach_understanding.md`：新增 `equipment_memory`，包含 `source_version`、完整 `source_text`、连续摘录 `value`、`scope`。复用一次千问理解调用，不加第二个提取 Agent。Pydantic 检查结构；业务代码另外核对来源版本、原话、已支持器械、遗漏的否定以及显式时间边界。这些检查不是完整语义正确性证明。
2. `services/equipment_memory.py` 与 `coach_reviews.py`：候选经过人工确认才应用；自动理解保留核对卡。`equipment_scope` 允许用户在确认时选择或修改范围。没有范围的候选返回 422，过期上下文返回 409。今天/本次不会直接改长期档案；长期复用统一档案事务写入。没有新模型调用的旧兼容响应若只填写 `training.equipment`，也会生成需要核对范围的候选。
3. `training_context.py` 和 `training_recommendations.py`：读取有效条件并核对档案版本、当天条件版本及日期。建议指纹包含这些状态，跨零点或更正后的旧结果标记过期。动作替换绑定当天条件版本：器械未改变时继续有效，改变后撤销依赖旧器械的替换。
4. `static/coach.js`、`coach_memory.py` 与 `coach_memory_digests.py`：页面展示候选、范围和实际建议来源。长期语义候选的原话绑定事实版本，更正后不再进入有效旧证据；本版临时器械原话不进入跨会话历史检索/摘要候选，当天事实直接从私人 SQL 装配，防止把临时信息误当成长期事实。

此前“在家，只有哑铃”等少量固定句式的兼容路径仍保留原来的长期保存提示和手动确认，不能声称它已经是开放式语义提取。当前直接器械修改命令继续作为本次条件使用。真实模型按新提示词输出结构化候选的质量，需要后续独立评测；测试替身只能验证接线和生命周期。

## 保存、更正、撤销与隔离

私人 schema v17 新增 `coach_day_equipment`，每账号最多一条当前条件，附日期、递增版本、档案版本、来源对话和轮次。更正覆盖当前值；删除来源聊天清空当前值，保留版本计数，防止旧值重新出现。当天 A→B→A 与长期 A→B→A 一样，不能复活旧草稿。没有从聊天历史扫描并猜测“上一个可用值”的回退。

当前撤销当天条件的页面入口是删除其来源对话；这会同时删除那段聊天。还没有独立的“只撤销今天器械”按钮。清空器械档案也会撤销当天条件，包括档案已经为空的情况。长期确认会取代当天覆盖，明确表明用户选择了新的长期事实。无关的档案修改不会清空当天条件。

删除来源聊天不会自动删除已经独立确认的长期档案；长期档案需要单独更正/清空。账号身份来自服务端认证；来源轮次需属于本人对话。当天表、档案、原话与摘要均在私人库，未写入公共 FTS 或向量索引。这里没有公共反馈发布、模型自动修改代码或自主学习新知识。
