## 与 Hermes 的准确对应

[Hermes 官方记忆说明](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)中的 `USER.md` 是精简用户画像，`MEMORY.md` 是 agent 的环境、约定和经验笔记；两者在**新 session 开始时**读取为冻结的系统提示词快照，并非每条消息重新读文件。旧 session 通过 `session_search` 按需找回。这里用“热、温、冷”解释 Fitness 的目标架构，是我们的映射，不冒称 Hermes 的正式三级 API。

| 层 | Fitness 中的含义 | 当前状态 |
| --- | --- | --- |
| 热 | 本次会话的待核对消息、已核对限制、当前任务状态 | 已有；不同业务入口按需读取 |
| 温 | 当前账号的已保存档案、显式保存的交流偏好/个人术语 | 档案字段原有；E2b 新增用户可编辑记忆条目，教练理解调用前读取，尚无 agent 自主写入 |
| 冷 | 本人完整旧对话、实际记录和已核对的旧对话摘录 | E2a 的旧原话词项找回和 E2b 的用户核对摘录已接线；无私人向量语义回忆 |

不要把“存进数据库”当成“模型每次看见”。`coach_reviews.py` 的理解调用读取本次消息、相关档案/训练事实和当前账号温记忆；遇到“上次”等才附历史证据与已核对的摘录。**训练建议**不靠旧对话检索猜设备，而是每次读取当前个人档案中的器械。`knowledge_answers.py` 的公共摘答只发送问题与公共候选摘录，不注入个人记忆卡。这是业务事实读取，并非 Hermes 式统一提示词记忆。

## E2b：已接线的受控温记忆

1. 已保存档案和实际记录仍是事实来源。schema v15 的 `coach_memory_entries` 按认证 `user_id` 隔离，只允许用户显式保存 `user_preference` 或 `assistant_note`；最多 20 条、共 1200 字，每条最多 200 字。页面/API 支持查看、更正和删除，有版本冲突检查；每次相关教练理解读取当前版本。这里的“助手笔记”是用户确认的个人术语，**不是模型自主管理文件**。食物过敏、禁忌、目标和器械等已有档案字段不复制为新的硬约束。
2. `coach_memory_digests` 允许用户点击“整理当前对话”，将最近最多三条已核对原话截取并拼成有原对话/版本出处的候选；没有 LLM 生成或事实改写。点击核对后才可在“上次”等历史指代中词项找回。原话变化则标为失效、需重新生成并核对；删除原对话会级联删除摘要。摘要始终是冷层历史证据，不能晋升成今天的限制。
3. [migrate_memory.py](../../../scripts/migrate_memory.py) 是 v14→v15 离线迁移入口：服务须先停，目标备份须为新私有路径；先做校验备份，迁移后比较旧表指纹。备份/恢复、预检已识别 v15，同时兼容读取旧 v13/v14 备份。未对正式私人库运行迁移，也未部署。

## E2c：统一装配，再评测

当前教练理解入口 `coach_reviews.py` 在请求前装配本轮消息/档案/会话限制、`warm_memory` 和按需历史原话/摘要，并将条目版本纳入上下文指纹；模型返回时复核变化。Fitness 是多用户 Web 服务，用户可能在同一对话期间改档案或过敏条件，因此每次相关理解请求重新读取已确认事实，不照搬 Hermes 只在 session 开始冻结文件的缓存取舍。一般公共知识摘答仍只用问题与公共证据。后续若新增其他个性化模型入口，再提取统一装配器；当前没有把全站调用伪装成已统一。

优先级：本轮明确器械条件在当前对话有效；用户手动确认的稳定器械语句写入档案，供新会话使用；随后修改档案会使旧对话器械失效。温层其他偏好不能覆盖硬约束；冷层是“以前说过”的证据，不能自动代表今天。冲突或来源不足时澄清，不静默选择。记忆有长度上限和按任务选择，不能把完整聊天塞进提示词。

例子：同一会话说“今天在家只有哑铃”是热层，不写档案；说“在家，只有哑铃”后，在页面看到即将更新档案的提示，并手动确认，才变成跨会话可用的个人器械。新会话只问“今天练什么”会按档案安排；把档案改为“在家，徒手”后，旧会话条件和旧器械检索结果不再覆盖新档案。当前持久化只认有限的明确句式与已识别器械，不将任意旧聊天自动晋升，也不自动判断器械何时损坏或用户何时换场地。

本轮验收把三层分开检查：保存与找回、最终训练建议采用器械、档案更正后重新建议及旧摘要抑制。`scripts/verify_equipment_memory_live.py` 使用一次真实千问调用理解合成原话，后续训练建议由受约束规则生成；临时库、合成账号、最多一次云模型调用，未触碰正式个人库。该单场景通过，但不是多用户真实使用质量统计，也不证明开放表达的记忆抽取能力。

合成数据和模型替身回归已覆盖跨会话指代、档案器械更正、历史摘要抑制、跨用户隔离、重启持久化及模型调用期间版本变化。新增页面单元检查数据转义和交互；此前 8771 隔离浏览器检查过温记忆保存/更正/删除和窄屏，**本轮器械提示尚未再做浏览器验收**。完整 Python 回归此前仍有两项已在原始基线复现的训练授权测试失败，详情见 [既有回归记录](RETRIEVAL_TEST_RESULTS.md)。尚需独立多轮质量集，分开比较“取回正确旧事实”“采用正确当前限制”“最终建议正确”，并报告 token/延迟代价；没有统计前不写提升百分比。

## Hermes 复用边界

借鉴其有界 `USER.md`/`MEMORY.md`、增删改、旧会话按需搜索与写入门禁。Fitness 已有 FastAPI、SQLite、多用户认证和业务档案，不直接复制 Hermes 的单 profile 文件目录或 agent runtime：共享文件有串号风险，直接复制也会和现有档案冲突。先复用机制和接口形状，再对已核实许可证及适配范围的具体源码作局部复用决定。
