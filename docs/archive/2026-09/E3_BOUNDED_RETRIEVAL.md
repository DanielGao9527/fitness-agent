# E3a：有界检索自纠正与合成回放

状态：2026-09-25 已接线、合成数据测试通过；真实模型效果与完整离线回放未验收。代码默认检索为 `hybrid + jieba`，旧双字仍可作为历史对照，不是当前默认。

## 为什么放在一次问答里

现有问答先检索公开摘要，再让受约束模型判断证据是否直接回答原问题。如果初次候选只是词语相近，模型只能返回“资料不足”。E3a 在**已有候选、模型明确判不足**时，允许模型建议一个更聚焦的搜索表达，再检索一次。第二次判断仍拿用户的**原问题**和新候选比较；改写只影响找资料，不替用户改提问，也不写入私人记忆或公共知识。

流程是：原问题 → 检索快照 1 → 证据判断 → 如不足且改写有效，检索快照 2 → 再判断原问题 → 按稳定 ID 复核来源 → 摘要与出处。没有初始候选、改写越过一般知识范围、第二次候选完全相同、第二次仍不足或达到两轮上限时立即停止。不会因为一次模型输出不合格、超时或额度耗尽而自动无限重试。

## 可追溯的边界

- 一次工作流最多 2 次公开资料检索、2 次证据判断；每个真实问题向量和判断模型调用都沿用已认证用户的额度。口语理解若发生，是额外且已有的前置调用。
- 主聊天的待核对条件、食物禁忌与健康范围在第二次候选上重新检查；一条医疗或个人处方改写直接拒绝。任何引用都必须属于当前轮候选，返回前按 ID、内容、状态与期限复核。
- 返回的 `retrieval.attempts` 只含阶段、候选公开 ID、运行模式、降级及停止原因，不保存改写后的原文、私人档案或向量。主聊天的同一消息和重复 HTTP 请求仍只启动一次工作流。
- 这叫**请求内纠正**。它没有跨请求学习、自动调整 RRF、自动把对话沉淀成知识，也没有证明回答准确率提高。
