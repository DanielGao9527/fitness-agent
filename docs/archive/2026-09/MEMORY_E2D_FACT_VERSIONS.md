# E2d.1：器械事实版本与来源（2026-09-27）

本增量覆盖器械字段的确认、更正、清空、来源及派生结果失效。代码已接线，最终验证记录见 EXECUTION/STATUS；不代表开放式语义记忆抽取、时间到期规则或知识自沉淀已完成。正式服务与私人库尚未切换。

## 为什么改

旧实现用档案器械的字符串锚定本轮条件。例如档案是 A“哑铃”，本轮临时选择“徒手”；后来档案改成 B，再改回 A，字符串又相同，旧临时条件及旧建议可能重新变为有效。理解期间发生 A→B→A，也可能通过旧指纹检查。新增六条回归在修复前全部失败，覆盖上述问题、历史摘录复活以及对话写档案丢失体测来源。

现在用单调递增的字段版本表达“这一次确认”。相同文字可以对应不同版本：

| 操作 | 档案器械版本 | 后果 |
| --- | --- | --- |
| 确认保存哑铃 | 1 | 长期事实在档案，本次条件绑定版本 1 |
| 本轮改用徒手 | 1 | 临时条件只属于当前会话，不改档案 |
| 档案改成泳池 | 2 | 绑定版本 1 的旧条件、理解和建议失效 |
| 档案改回哑铃 | 3 | 文字相同也不等于版本 1，旧临时条件不会恢复 |
| 重复保存同一值 | 3 | 不制造更正事件，已有有效临时条件保持 |
| 明确清空器械 | 4 | 当前事实撤销，重新建议需要明确器械 |

这是状态和并发控制，不能用向量相似度替代，也不需要额外模型调用。

## 实现位置与数据流

1. `services/profile_facts.py`：读取版本、原子写入事实与元数据、查询当前来源。器械值始终只在 `profiles.equipment`；新增 `profile_fact_events` 只保存账号、字段、递增版本、设置/清空、来源种类、原对话/轮次及时间，不保存新旧器械正文。当前版本由索引读取最新事件，前一版本即被替代。
2. `services/records.py` 与 `coach_reviews.py`：档案保存和对话手动确认共用上述写入函数。明确提供器械且值变化才递增；首次明确确认可建立版本。页面的自动理解遇到长期器械候选时保留 ready 草稿和核对按钮，不再提前自动消费该草稿；手动确认前不保存长期器械。其他不含长期候选的自动应用仍按原业务执行。重复确认保持幂等。对话只改器械时保留原有体测基线与来源元数据。
3. `training_context.py`：本轮器械条件附 `profile_revision_basis`。读取时与当前版本核对，失效器械及依赖它的动作替换不再参与本次建议；保留原始历史响应。没有版本的旧条件不猜测仍有效，需要新补充，建议优先读取当前档案。
4. `coach_reviews.py` 与 `training_recommendations.py`：版本进入理解与最终建议的指纹。模型返回前、人工确认时、重复请求及展示旧建议时均校验，覆盖没有临时覆盖的纯档案建议。
5. `coach_memory.py` 与 `coach_memory_digests.py`：已核对器械原话绑定当时版本；被替代后不再提供为有效历史证据。摘要的可用来源随之变化，旧审批变为过期。非器械内容仍按原规则处理；有限句式以外的记忆尚未统一纳入这一机制。
6. `api/routes.py` 与 `static/app.js`：档案 GET/PUT 通过 `X-Equipment-Revision` 返回对应快照版本。页面保留渲染当时的版本，提交带上同名请求头；过期保存返回 409，整个档案保存事务不提交。为兼容旧 API 客户端，请求头目前可选：没有版本头的旧调用仍属于显式无前置条件保存，不能声称所有外部调用都有乐观锁。模型及确认路径的指纹检查不依赖此请求头。

`GET /api/profile/facts` 只返回当前认证账号的器械版本/来源信息；不接受请求方指定另一个 `user_id`。本轮页面继续显示原有“来自个人档案/当前对话”的器械提示；详细元数据可经该接口查询，尚无完整审计时间线页面。

## 删除与隐私边界

- 删除源聊天：历史原话和摘要按既有流程删除；事件的对话外键变为空。已单独确认保存的档案事实保留，并标记来源聊天已不可用。
- 撤销档案器械：在档案显式清空，增加 clear 版本；旧派生条件失效。它不等于同时删除全部聊天原文；需要删除聊天时走聊天删除操作。
- 删除账号：事件随本人账号级联删除。审计事件不另存私人正文，不进入公共 FTS 或向量缓存。
- 不把旧聊天自动升级为权威事实；模型抽取仍限于原有可校验句式和用户手动确认。

## 迁移与运行

私人 schema 升为 v16，共 23 张业务表。v16 只新增事件表及索引；已有档案中的器械以版本 1、来源 `legacy_profile` 建立基线，不推断原聊天或原确认时间。原表内容保持不变。新库无需外部依赖；备份/恢复工具兼容 v13–v16。

`scripts/migrate_memory.py` 支持停服后的 v14/v15→v16：先新建并验证备份，再迁移，核对原表指纹。v13 仍使用 `migrate_guests.py` 升到当前结构。发布器保留结构差异保护。本轮只在合成数据库迁移，不运行正式库维护。普通本地启动仍会按现有机制自动升级旧库并留下 `.pre-v16.bak`，因此不要未经维护流程直接对正式库启动新代码。

启动方式仍见 `scripts/start.ps1` 和 CONFIGURATION；无需新配置或增加云 API。隔离页面演示使用以下两个终端，Python 指向本机项目虚拟环境，Node 需能加载 Playwright：

```text
python tests/ui_fixture_server.py --fact-versions
node tests/browser-profile-facts.cjs
```

该测试服务只绑定 127.0.0.1:8772，使用临时合成库、词法检索和模型替身。测试后停止本次测试进程，不停止已有正式服务。后端专项入口为 `tests/test_profile_fact_versions.py`；还需运行已有记忆、档案/体测、训练、备份与迁移回归。
