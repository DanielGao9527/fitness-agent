# 产品范围

核对：2026-10-19。用户决定维持当前项目，完成收尾后学习代码；不接小模型微调，不增加业务功能、框架或知识库规模。

Fitness Agent面向一般成人的中文饮食记录、剩余餐次规划与当天训练建议。当前交付按以下四项能力组织：

1. **中文混合检索**：jieba＋SQLite FTS5/BM25与阿里云Embedding双路召回，经RRF融合、内容/身份匹配缓存、来源复核及词法降级。知识为有出处的审核摘要，不是自动采集或自由生成事实。
2. **多轮理解与安全写入**：文字、主动录音和饮食照片辅助生成结构化草稿；用户核对后明确保存。幂等键、版本与上下文指纹阻止重复写入和过期结果。
3. **受约束多餐规划**：LLM给出有限食材候选，本地MILP联合配量并独立复算；结合已吃记录、营养范围、禁忌、保留项及份量上限，给食材和份量，不给做法；无解明确失败。
4. **个人记忆与证据治理**：会话、权威档案/已确认笔记、历史证据分层；跨会话采用个人条件，结合近七天实际训练，更正/删除使旧结果失效。证据不足时有界重检索；公共摘录经独立质量要求和人工批准后才可切换。

## 已定边界

- 过敏、明确禁忌、近期伤病及器械条件不能为推荐成功率放宽；有限规则/结构校验不称完整语义安全系统。不提供医疗饮食、伤病康复处方或训练照片。
- 训练只安排今天。三/四/五分化、明确器械、经验、时间和实际记录参与编排；计划和建议不算完成。没有周/月自治规划。
- 身份来自认证会话，模型或正文中的user_id不能改变归属。私人档案/事实/记忆在用户数据库，公共知识独立存储。
- 估算保留范围、假设与来源。正式饮食记录需明确食物及基本份量，不强制称重、不虚构确定克数。
- 无密钥仍可使用账号、档案与手动记录；缺模型、缺证据、来源失效或无可行解都明确返回状态。
- 不新增微调、自动知识提取、跨请求策略自优化、多个自治Agent、支付、社交或穿戴接入。
- 公网和实体设备、正式公共知识发布单独验收；本地工程交付不等于上述环境或质量已通过。
