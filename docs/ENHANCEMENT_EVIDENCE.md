## E1：已有可用于简历的真实量化

**改法。** jieba 搜索分词＋SQLite FTS5/BM25 与阿里云 text-embedding-v4（1024 维）并行召回，每路取前 20，以等权 RRF（k=60）融合；向量缓存绑定模型身份、维度、模板和内容哈希，引用前复核来源，向量不可用时明确退到词法。jieba 负责分词，知识摘要分块是另一件事。

**对照条件。** T2Retrieval 的固定 100 题和 1,000 篇文档；随机种子 20260924；各方法使用相同文本前 6,000 字符、相同相关性标签。候选池含全部 500 篇正相关文档和 500 篇随机干扰，10 篇文本被截短。这是缩小候选库的外部检索组件实验，不是官方全库成绩，也不是 Fitness 用户问答准确率。

| 同题消融 | Recall@6 | MRR@10 | nDCG@10 |
| --- | ---: | ---: | ---: |
| 旧双字 FTS5/BM25 | 72.11% | 0.9342 | 0.8206 |
| 仅 jieba FTS5/BM25 | 70.74% | 0.9158 | 0.8061 |
| 纯向量 | 88.51% | 0.9733 | 0.9672 |
| 双字＋向量 RRF | 83.29% | 0.9695 | 0.9411 |
| 当前 jieba＋向量 RRF | 84.16% | 0.9642 | 0.9326 |

Recall@6 的含义：每题前六条找回的已标注相关文档占全部已标注相关文档的比例，再对问题取平均。绝对变化为 `(增强值－基线值)×100` 个百分点；本实验为 **增加 12.05 个百分点**。不要把它写成“回答准确率提高 12.05%”。

仅更换 jieba 的这组结果下降 1.37 个百分点；当前融合比纯向量低 4.36 个百分点。现有结果支持“相比原词法配置改善召回”，不支持“jieba 单独提升整体召回”或“混合一定优于纯向量”。当前双路方案是用户选定的实现，词法降级的价值与融合排名收益分别解释。

**证据。** [逐题原始结果](../evals/results/t2-pilot-2026-09-25.json)、[实验条件与不利案例](archive/2026-09/T2_RETRIEVAL_EVALUATION.md)、[现有评测脚本](../scripts/evaluate_t2_pilot.py)。完整缓存可离线重放，缺缓存停止；本轮没有重新调用模型或重新选择样本。成功实验的 110 次向量请求/543,680 输入 token 不含此前失败尝试，不能当整个任务总费用。

**当前可用简历句。**

> 以 jieba＋FTS5/BM25 与阿里云 Embedding 构建中文双路召回，经 RRF 融合、版本化缓存和来源复核；在 T2 固定抽样的 100 题、1,000 文档对照中，Recall@6 从旧双字词法基线的 72.11% 提升至 84.16%，增加 12.05 个百分点。

面试追问时同时说明纯向量 88.51% 及上述抽样边界。

## E2：记忆优化的贡献与已有前后对照

**业务目标。** 同一句“只有哑铃”需要知道适用时段和来源；新的档案更正必须压过旧会话条件。仅把历史发给模型，不能证明最终建议实际采用了它。

**改法。** 复用会话、档案和历史证据；器械候选携带用户原话/轮次及本次、今天、长期范围，确认后写相应权威入口；以字段/集合递增版本和上下文指纹使更正、到期、撤销及 A→B→A 后的旧结果失效。偏好笔记有来源与删除机制，硬约束继续使用档案。入口为 [equipment_memory](../services/equipment_memory.py)、[profile_facts](../services/profile_facts.py)、[training_context](../services/training_context.py)。

**已经量化的后端修复。** 固定 2026-09-28 的旧模型响应，只回放开发集：60 个计划场景中 55 个有可回放输出，5 个缺响应单列，新增云调用为零。

| 同一批可回放输入 | 原处理 | 修复后处理 | 解释 |
| --- | ---: | ---: | --- |
| 业务校验后候选严格匹配 | 35/40 | 40/40 | 后端处理改善，增加 12.50 个百分点 |
| 应补问场景明确补问 | 0/15 | 15/15 | 这些已知开发场景的补问流程修复 |
| 模型原始候选严格匹配 | 29/40 | 29/40 | 原始响应固定，模型提取没有改变 |
| 最终建议器械及来源匹配 | 75/75 | 75/75 | 本批没有观测到该指标继续提高 |

这组数只能称“固定响应下的后端开发回放”，不能称记忆准确率或新提示词质量提升。见 [前后逐项表](../evals/results/memory_v1_dev_replay_final_20260929/REPORT.md) 与 [机器可读汇总](../evals/results/memory_v1_dev_replay_final_20260929/summary.json)。

另有首版真实千问评测：98 组已运行、2 组未运行；113 次尝试、99 次响应、14 次供应商失败。器械及来源匹配 112/128，留出为 36/48；这两个分母是建议检查次数，不是独立用户数，也没有匹配的旧版真实对照。[原始报告](../evals/results/memory_v1_report_20260928/REPORT.md)不得与上述开发回放拼成一个提升率。

2026-10-15 的 qwen3.6-plus 单场景又验证了“确认长期哑铃→新会话建议采用→改徒手→旧建议失效/旧历史零命中→徒手动作”。理解使用真实模型，动作编排使用本地受约束规则；[小场景记录](../evals/results/real-acceptance-qwen36-2026-10-15.json)不外推总体准确率。

**下一轮基线。** 历史增强前代码候选为 07b6ec2，须先验证其在隔离库上与相同评测协议的兼容性；当前不能填写旧版得分。两边固定 qwen3.6-plus、相同合成档案/输入/确认操作、日期和最终建议判分，分别统计原始提取、校验后事实、最终器械/来源、旧条件误用、补问和失败。历史 qwen3.7-plus 与当前 qwen3.6-plus 的不同题成绩不能直接相减归因于记忆优化。

**当前简历措辞。** 可描述分层读取、明确确认、来源追踪、范围与版本失效等工程贡献；整体提升率待配对真实评测后填写。完整新表达的独立复核尚未完成。

## E3：怎样量化检索循环的收益与代价

**改法。** [knowledge_answers](../services/knowledge_answers.py) 与 [knowledge_policy](../services/knowledge_policy.py) 在首轮零命中或证据不足时，最多进行一次合法查询改写并重检索；每轮仍判断原问题和当前有效引用。有限词面校验保留数字/单位、时段与否定，重复证据停止，远程调用计入认证额度，使用 45 秒协作式截止；不是完整语义等价证明或强制抢占超时。

**主对照。** 同一代码/模型/语料/参数，以 `KnowledgePolicy(max_rounds=1)` 为单轮消融，以 `max_rounds=2` 为当前方案，固定相同时间预算。只改变轮数，比较有依据摘答、证据不足时正确停止、负收益、远程调用、token 及实际端到端耗时。该对照从一般知识问答入口开始，不评价整个主聊天分流器。

**历史增量另记。** 1e5367f 的 E3a 已有“非空但不足”时的两轮能力；a24c534 的 E3b 进一步补了零命中恢复、有限改写检查、截止和回放。单轮消融不能伪称“E3b 开发前完全没有循环”。若要专门宣称 E3b 增益，须另外运行历史 E3a 与当前版的同题对照。

| 要量化的指标 | 固定计算方式 |
| --- | --- |
| 有依据摘答率 | 在已复核可答题中，引用有效且覆盖原问题必要信息的摘答数/可答题数 |
| 正确不足率 | 在已复核缺证据题中，明确不足且不拿相近主题摘录冒充答案的题数/缺证据题数 |
| 增益/负收益 | 同题单轮错→两轮对、单轮对→两轮错分别计数；净变化为两者之差/相同完整题集数 |
| 调用与费用 | 分开记录 embedding、判断调用及失败；检索本地操作不当作云调用。token/账单缺失填未知，不由调用数编造金额 |
| 延迟 | 相同运行方式下实际端到端时间，另列编码/判断阶段；小样本展示全部观测及均值/P95，不声称稳定线上 SLA |

现有 [24 个固定响应流程](../evals/retrieval_loop/v1/README.md)只验证契约，不提供上表真实收益。本轮新准备的 24 题语义草案见下一节，当前没有得分；预期结果不是已测结果。

## E4：治理能力与效果指标分别交付

工程链路为私人反馈→有出处公共摘录→人工预审→独立构建/登记→服务端质量检查→人工批准→明确切换/回滚。候选、来源、角色及协议/缓存版本绑定，失效时停止引用；私人记忆不进入公共知识。入口为 [knowledge_publications](../services/knowledge_publications.py)、[knowledge_quality](../services/knowledge_quality.py) 与 [knowledge_runtime](../services/knowledge_runtime.py)。

[工程结果](../evals/results/knowledge-publication-checks-2026-10-15.json)记录应用测试目录一次 1,984 项、发布器另 36 项通过，两批单独报告；不能将测试通过率称为模型准确率，也不能宣称每项测试都是本次新增。正式协议仍 pending_review，本机未发布实际候选。

未来效果需要固定同一批可审公共候选，分别检查正确批准/拒绝、失效引用、回滚失效时间及原知识质量退化；操作耗时只有实测后才填写。当前 0.80 是召回验收下限，不是测出的提升。完整治理简历表述按 DELIVERY 的正式验收条件再定稿，不写“自动从高质量对话学习”。

## 本轮离线准备与后续填数规则

唯一准备包为 [preparation_v1.json](../evals/acceptance/preparation_v1.json)，不是生产发布协议，也没有接入运行时：

- **记忆复核表：** 为现有新表达 v2 的 24 条逐条生成复核索引，带原文件行号、案例哈希、场景族和开发/留出划分；所有复核结论为空，原题与标签仍以原文件为准。原始题集哈希和正式复核状态均未改写。现有 `--plan` 核对为单个版本最多 27 次理解调用。
- **检索语义草案：** 24 条自建题，12 个主题族，开发/留出各 12；暂拟可答 16、证据不足 8，逐题给候选出处、判分关键点和错误回答反例。根据公共摘要拟定，尚未独立逐题复核；没有使用本草案的检索或模型结果筛题，也不称外部或盲测基准。正式运行前需形成明确的冻结版本。
- **控制条件：** 固定来源哈希/有效日期、模型/提示词、向量身份、分词/融合参数、账号条件与代码哈希；输出按案例 ID 配对。候选参考答案、错误示例与判分字段仅供评审，不能送进被测模型。发现有效替代证据时两边同规则复核，不只给有利方案补标签。
- **失败处理：** 供应商失败、超时及未运行项单列；完整批次未结束，不宣称完整题集提升。正式质量评审宜隐去方案名称；作者生成的空复核表不是独立审核凭据。
- **保留反例：** 静态检查发现草案 01 的一般频率问法含“安排”，会触发现有范围词面拦截；原问题和标记保留，待核对一般资料与个人安排的边界。这不是主聊天或模型的实际运行结果，也不据此填写准确率。24 条与既有 260 QA 无归一化后完全相同的问题，但主题重叠，不能当作未见独立基准。
- **调用计划：** 这轮实际云请求为 0；原小场景预算仍为已记 9/20。完整记忆 v2 单个版本最多 27 次；若两个版本均按此协议规划，上限为 54 次。24 题单轮/两轮对照在文档向量已具备、无额外分流/裁判调用时，上限为 `24×(2+4)=144` 次远程请求；这是上限规划，不是已获授权或实际费用。现有评测器和真实语义对照执行接线需在运行前核对，不自动启动新批次。

以后每个新结果只按一张证据卡追加：`问题 → 对照版本/配置 → 为什么改 → 实际方法 → 相同题集/分母 → 基线值 → 增强值 → 绝对差值 → 调用/时间代价 → 失败与局限 → 原始报告 → 可用简历句`。未测填“未测”，不可比填“不可直接比较”。

当前最强的数值证据是 E1 的外部抽样召回；E2 有明确限定的后端回放结果；E3/E4 的真实增益仍待验证。下一步先完成复核与基线运行兼容性，不为简历预设目标百分比。
