# 架构与数据流

Fitness Agent 是一个单体 Web 应用：FastAPI 同时提供 API 和网页静态资源；前端使用原生 JavaScript，私人业务数据保存在 SQLite。语言、语音和照片理解通过后端按需调用模型，浏览器不持有供应商密钥。

```text
浏览器页面 static/
    ↓ 同源 HTTP，请求携带登录会话
FastAPI app.py / api/
    ↓ 校验参数与用户身份
业务服务 services/
    ├─ database.py → 私人 SQLite：账号、档案、记录、对话及草稿
    ├─ rag/ → 公共资料清单 + 独立 FTS5 检索索引
    ├─ data/nutrition、data/training → 审核候选和参考
    └─ model/ + prompts/ → 可选千问调用
```

## 模块职责

| 位置 | 职责 |
| --- | --- |
| `app.py`、`config.py` | 应用生命周期、环境配置、中间件和访问模式 |
| `api/`、`schemas.py` | 路由、输入校验、认证会话及返回契约 |
| `security.py` | 密码哈希、会话及认证相关工具 |
| `database.py` | 私人数据表、迁移及连接管理 |
| `services/` | 记录、目标、对话、推荐、营养配量和版本校验 |
| `model/` | 模型供应商适配、超时、结构化输出及错误分类 |
| `prompts/` | 应用调用模型时使用的任务提示词 |
| `rag/` | 审核资料加载、检索、有效期与出处检查 |
| `agent/` | 有界工具适配及早期通用接口兼容；当前助手编排主要在 services |
| `static/` | 页面、表单、对话、草稿保护与错误呈现 |

## 记录与建议

饮食、训练和体测只有用户明确保存才成为实际记录。AI 解析、营养估算和助手推荐是待核对内容；生成建议不会自动写入实际记录。幂等键防止重试重复写入，版本和事实指纹用于拒绝过时结果。

身份始终来自已认证会话，接口不信任请求正文或模型生成的 `user_id`。按用户隔离数据，模型返回后再次核对用户归属、输入版本和相关条件。

## 饮食与目标

用户描述先形成待确认草稿，估算保留范围、假设和来源。目标来自已保存档案及用户明确选择的调整，今日覆盖优先。配餐由审核候选、模型选材与本地数值求解配合，最终重新检查营养区间、过敏禁忌、食材选择和修改范围。

已吃记录与建议分开计算。未知营养不当作零；无法满足约束时说明缺口，保留原建议，不伪造达标结果或无条件重复调用。周期反馈是有界工程估算，不声称测得真实全天消耗。

## 训练建议

当前提供三、四、五分化下的当天建议，结合已保存档案、明确器械、时间及本人近七日实际完成内容。组次受结构、经验与时间限制；可用时间与预计训练时长分开显示。

部分历史接口和数据仍为兼容保留，不代表页面继续开放旧周计划。实际记录、建议和可选历史负重参考分别处理；没有可比较事实时不猜初始重量或自动加重。

## 知识与模型

公共资料是带出处、审核状态、范围和复核期限的清单。FTS5 索引与私人记录分离；应用运行时不自动从网络补齐知识，不把私人档案写入公共知识库。详情见 [资料说明](KNOWLEDGE_SOURCES.md)。

模型能力可独立关闭。缺少配置时账号和手动记录仍可运行，AI 接口返回明确状态。请求设超时与次数限制，失败不自动重试；这些限制不等于供应商账单的绝对金额上限。

## 部署边界

共享模式要求明确 HTTPS 域名、Host 白名单、安全 Cookie 和关闭注册；关闭交互式调试文档，匿名健康接口不返回具体模型型号。认证后的建议结果保留来源元数据。应用以单 worker 运行，SQLite 与模型 Key 位于发布目录之外。反向代理只访问本机应用端口，见 [部署说明](DEPLOYMENT.md)。

应用面向一般成人健身记录与建议，不提供医疗、伤病康复处方、支付、社交或穿戴设备接入。
