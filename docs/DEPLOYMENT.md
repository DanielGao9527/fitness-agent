# 部署与自动更新

本项目适合从单台 Linux 服务器开始：FastAPI、同源网页和 SQLite 同机，Caddy 提供 HTTPS，systemd 管理进程。服务器调用模型接口，不需要 GPU；实际并发能力仍需按使用场景测量。

## 发布流程

```text
本地功能分支 → GitHub 合并 main → Linux 离线检查
                                   ↓ 通过且开启发布
                              更新 deploy 分支
                                   ↓ ECS 定时读取
                        安装新版本 → 核对 → 切换服务
```

检查与发布使用同一个提交。服务器只在发布分支 SHA 变化时更新，部署时串行处理；数据库、上传文件、备份和环境变量位于代码版本目录之外。日常更新无需人工上传压缩包。

默认不启用自动发布：先完成服务器初始化和首次验证，再开启仓库 `DEPLOY_ENABLED` 变量。具体工作流、配置路径、安装命令和恢复边界以 [deploy/README.md](../deploy/README.md) 为准。

## 首次部署顺序

1. 准备 Python 3.12、Git、持久磁盘和服务账户；代码与数据使用不同目录。
2. 在目标 Linux 上安装锁定依赖，检查 FTS5、NumPy/SciPy 和离线测试。Windows 测试结果不能代替 Linux 验收。
3. 先保持模型关闭，通过本机或 SSH 隧道建立独立试用账号；不上传开发电脑的私人数据库。
4. 确认域名归属、地区与适用的备案要求，配置 DNS 与 HTTPS。
5. 设置共享模式、明确 Host、安全 Cookie，按需要独立开启注册和游客，建立私密备份及恢复流程。已有v13数据库须先按[账号与游客](ACCOUNTS.md)进行维护迁移。
6. 验证登录、用户隔离、记录保存、重启持久化，再按需求启用服务端 AI 能力和费用上限。
7. 验证发布和恢复流程后开启自动部署，最后进行真实手机和网络体验验收。

## 网络与运行方式

网页入口通常使用 80/443；应用监听 `127.0.0.1:8765`，不开放数据库或应用端口到公网。SSH 管理限制来源；自动部署采用服务器主动拉取，不要求向 GitHub 执行器开放 SSH。

HTTPS 反向代理只信任明确的本机代理，保留请求体上限；静态资源可压缩，语音/照片上传上限由后台继续检查。生产不使用开发重载或多 worker。

中国内地服务器对外提供网站前，需核对并完成适用备案。域名已经购买不代表已经备案；安装和私密验收可先进行。[阿里云备案流程](https://help.aliyun.com/zh/icp-filing/basic-icp-service/getting-started/quick-start-for-icp-filing-for-personal-websites)

## 发布检查

- GitHub 仅包含代码、必要说明和公开资料；真实环境文件、数据库、日志、备份和运行索引均排除。
- 模型 Key 只在服务器；自动测试使用替身，不携带真实调用凭据。
- 自动化只发布可信正式分支，不执行外部贡献者提供的生产命令。
- 服务切换失败保留或恢复旧代码；有数据库结构变更时另外规划兼容迁移，不把代码回退当作数据库恢复。
- 源码公开与应用账号权限分开：查看 GitHub 不会获得网站管理或数据库访问权。

目前的配置文件是可执行方案，实际是否已部署应以 Actions、目标服务器状态和验收结果为准。

注册/游客版本新增v14数据表，不属于直接推送main即可无维护升级的版本。自动发布的结构保护保持启用，旧库会停在切换之前。此版本应先在功能分支完成检查，再与服务器维护者安排迁移、固定发布器更新及开关调整；不要强推deploy或删除结构保护来绕过检查。
