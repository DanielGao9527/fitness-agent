# 开发与交接约定

业务源码位于 `fitness-agent/data/runtime/remote-auth`。外层app.py、scripts/start.ps1和scripts/setup.ps1统一指向该增强实现及原账号数据库；不要恢复外层历史业务作为第二份运行版本，也不要修改原教学项目。

## 开始

1. 阅读PRODUCT、ARCHITECTURE、EXECUTION、STATUS、ROADMAP；完成标准见DELIVERY，演示入口见DEMOS。
2. 检查分支和已有改动，保留用户工作。增强交付分支为 `codex/fitness-hybrid-retrieval`，当前源码/本机库v23、39表。
3. 最新用户范围优先。本轮只完成五个既有演示和文档，不加功能、不扩知识库；现已收尾，后续从ROADMAP保留项按新授权推进。

## 实现边界

- 保持Python代码直接，复用现有服务；不为亮点增加无用途框架、更多记忆层或多个自治Agent。
- 身份来自认证会话，正文/模型不能指定数据归属；私人档案/记忆/实际记录与公共知识分开。
- AI输出是建议或候选，事实保存/实际入账/计划替换需要明确操作。重试不重复写入，更正、撤销、到期和删除须使受影响旧结果失效。
- 过敏、明确禁忌、近期伤病、器械范围与来源检查不能为提高通过率放宽。有限结构/规则校验不称为完整语义安全系统。
- 不将建议或计划算成实际完成，不用历史模型答案替代事实；训练仍只安排今天、读取近七天实际完成。
- 文档控制开发，prompts控制运行时模型行为；模板存在不等于已接线或真实调用通过。

## 验证与交付

- 改账号/事实/记录时覆盖认证、隔离、输入、并发、重启、更正/撤销和旧结果失效；测试用临时账号/数据库，不在日常8765造测试记录。
- 原库升级/重启已获本机授权，但仍须备份核验，保留原账号/记录/额度；不擅自部署公网、购买服务或改变计费。
- 供应商请求、模拟调用、缓存复现、固定响应回放和独立质量评测分开。留出不用于调参，不覆盖旧分数、失败或不利方案。
- 只提交代码、测试和必要技术说明/匿名汇总。个人文案、录像/截图、原始响应、数据库、凭据和上传图片不能进Git或常规日志。
- 更新STATUS的事实、ARCHITECTURE的实现、ROADMAP的方案状态及EXECUTION接续点；详细历史留报告/归档，不再往当前文档追加长时间线。
- 推送后核对**对应提交**的GitHub Actions，失败查日志并修复；未结束就明确待验证。不得用上传成功/本地通过代替远端通过，也不强改历史或跳过测试来显示绿色。
- 业务源码未变时不无意义重复本地整仓测试；演示录制按原清单复核，文档推送仍接受远端完整检查。
